## 1. 产品概述

### 1.1 产品一句话

Notch AI Monitor 是一个面向 Mac 用户的 AI CLI 会话监视器。它默认隐藏在 MacBook 刘海区域附近，只在 AI 会话需要用户介入时，以轻量胶囊、表情状态和下拉面板提醒用户处理。

### 1.2 核心价值

- 不把 AI 工具的普通运行状态变成持续打扰。
- 在多个 AI CLI 同时运行时，自动挑出最需要用户处理的一件事。
- 对确认、结果、错误、风险四类事件提供就近处理入口。
- 使用更接近 macOS 的简单、高级、低占用设计语言。

### 1.3 目标用户

- 同时使用 Claude CLI、Codex CLI、Qwen CLI 等多个 AI 工具的开发者。
- 用 AI agent 执行长任务、生成代码、整理文件、批量处理内容的用户。
- 对命令执行风险、终端窗口切换、任务完成提醒有较高敏感度的 Mac 用户。

### 1.4 用户痛点

| 痛点 | 当前表现 | 产品解决方式 |
| --- | --- | --- |
| 多个 AI 会话同时运行，很难知道谁在等我 | 终端窗口分散，用户需要来回切换 | 聚合会话，按事件优先级展示最重要事件 |
| AI 生成命令可能危险 | 用户容易漏看命令影响范围 | 风险事件主动探出，并展示证据和拒绝/允许动作 |
| 任务完成后没有轻量提醒 | 用户需要主动回终端确认 | 完成态用低打扰胶囊提示，可以打开结果或标记已读 |
| 出错信息埋在终端里 | 用户发现晚，重试成本高 | 错误态提示，面板提供日志、重试、忽略 |
| Mac 桌面空间宝贵 | 常驻窗口或大通知很重 | 默认隐入刘海，只在必要时出现 |

## 2. 产品原则

### 2.1 Mac 设计语言原则

1. 少即是多：顶部只展示一个当前最重要事件，不堆叠信息。
2. 低占用：无事时接近不可见，有事时只露出必要状态。
3. 就近处理：胶囊在哪里，面板就从哪里落下。
4. 清晰层级：右侧处理事件，左侧管理会话。
5. 不靠视觉花哨解决信息问题：风险必须给证据，错误必须给恢复动作。

### 2.2 产品行为原则

1. 只有需要用户注意的事件才打断用户。
2. 风险高于确认，确认高于错误，错误高于完成。
3. 普通运行状态只进入会话聚合，不主动显示。
4. 事件被处理后，自动切换到下一个待处理事件。
5. 没有事件时，产品回到休眠状态。

## 3. MVP 范围

### 3.1 MVP 必须包含

- macOS 顶部刘海/菜单栏附近的状态胶囊。
- AI 会话列表和会话状态聚合。
- 事件队列和优先级排序。
- 四类事件：风险、确认、完成、错误。
- 右侧事件胶囊：表情、状态词、事件数量。
- 左侧会话胶囊：会话聚合入口。
- 操作面板：事件详情、证据、命令/结果入口、动作按钮、事件分页。
- 会话面板：所有会话、会话状态、待处理数量。
- 基础偏好：通知策略、自动探出策略、监控工具开关。
- 键盘和可访问性基础能力。
- 演示/调试模式与正式体验分离。

### 3.2 MVP 暂不包含

- 完整云同步。
- 多用户团队协作。
- AI 自动解释复杂日志。
- 复杂规则引擎编辑器。
- 历史事件长期归档和高级搜索。
- Windows/Linux 适配。

## 5. 核心概念定义

### 5.1 会话 Session

会话代表一个正在被监控的 AI CLI 进程或任务上下文。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | string | 是 | 会话唯一 ID |
| `tool` | enum | 是 | `claude`、`codex`、`qwen`、`custom` |
| `name` | string | 是 | 展示名，例如 `Claude CLI` |
| `mark` | string | 是 | 胶囊短标识，例如 `CL` |
| `source` | string | 是 | 来源应用，例如 `Terminal`、`iTerm` |
| `project` | string | 否 | 项目名或仓库名 |
| `cwd` | string | 否 | 当前工作目录 |
| `processId` | number | 否 | 进程 ID |
| `windowId` | string | 否 | 终端窗口 ID |
| `tabId` | string | 否 | 终端 tab ID |
| `state` | enum | 是 | `idle`、`running`、`waiting`、`blocked`、`completed`、`failed` |
| `since` | datetime/string | 是 | 当前状态开始时间 |
| `lastActiveAt` | datetime | 否 | 最近活动时间 |
| `muted` | boolean | 是 | 是否静音普通事件 |

### 5.2 事件 Event

事件代表一个需要展示或处理的 AI 会话状态变化。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | string | 是 | 事件唯一 ID |
| `sessionId` | string | 是 | 所属会话 |
| `type` | enum | 是 | `risk`、`confirm`、`result`、`error` |
| `priority` | number | 是 | 优先级分数 |
| `status` | enum | 是 | `active`、`resolved`、`ignored`、`expired` |
| `title` | string | 是 | 面板标题 |
| `summary` | string | 是 | 一句话摘要 |
| `command` | string | 否 | 命令预览或结果入口 |
| `source` | string | 是 | 来源描述 |
| `createdAt` | datetime | 是 | 创建时间 |
| `updatedAt` | datetime | 否 | 更新时间 |
| `evidence` | object | 条件必填 | 事件证据，风险/错误/确认必须有 |
| `reasons` | string[] | 否 | 风险原因列表 |
| `actions` | Action[] | 是 | 可执行动作 |
| `resolvedAt` | datetime | 否 | 处理时间 |
| `resolution` | string | 否 | 处理结果 |

### 5.3 证据 Evidence

证据用于让用户判断是否信任一个事件。

| 字段 | 类型 | 场景 | 说明 |
| --- | --- | --- | --- |
| `reason` | string | 全部 | 为什么产生该事件 |
| `impact` | string | 风险/确认/错误 | 影响路径、进程、输出或权限 |
| `origin` | string | 全部 | 事件来源：AI 生成、用户触发、系统检测 |
| `rollback` | string | 风险/错误/确认 | 是否可撤销，如何恢复 |
| `affectedPaths` | string[] | 风险/确认 | 涉及的文件路径 |
| `riskLevel` | enum | 风险 | `low`、`medium`、`high`、`critical` |
| `logExcerpt` | string | 错误 | 错误日志片段 |

### 5.4 动作 Action

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | string | 是 | 动作 ID |
| `label` | string | 是 | 按钮文字 |
| `style` | enum | 否 | `primary`、`danger`、`secondary` |
| `resolves` | boolean | 是 | 执行后是否关闭当前事件 |
| `requiresConfirm` | boolean | 否 | 是否需要二次确认 |
| `sideEffect` | enum | 是 | `none`、`clipboard`、`process`、`filesystem`、`navigation` |
| `enabled` | boolean | 是 | 是否可点击 |
| `disabledReason` | string | 否 | 禁用原因 |

## 6. 状态机设计

### 6.1 情绪 mood

| mood | 对应事件 | 颜色 | 表情 | 说明 |
| --- | --- | --- | --- | --- |
| `none` | 无事件 | 灰 | 休眠眼 | 没有待处理事件 |
| `waiting` | `confirm` | 紫 | 眨眼/张望 | 等待用户确认 |
| `happy` | `result` | 柔和薄荷绿 | 圆点眼/小微笑 | 结果已完成 |
| `sad` | `error` | 蓝 | 泪滴/下撇嘴 | 出错或失败 |
| `angry` | `risk` | 红 | 怒目/紧抿嘴 | 高风险命令或危险操作 |

### 6.2 展示状态 state

| state | 含义 | 触发 | 可见内容 |
| --- | --- | --- | --- |
| `dormant` | 休眠 | 无事件 | 刘海内睡眠眼 |
| `glance` | 一瞥 | 非风险事件静息态 | 右侧小胶囊，必要时弱显示 |
| `peek` | 探出 | 风险自动、悬停/聚焦 | 左右胶囊完整露出 |
| `expanded` | 展开 | 点击左/右胶囊 | 对应面板打开 |

### 6.3 mood 到静息 state 的映射

| mood | 静息 state |
| --- | --- |
| `none` | `dormant` |
| `angry` | `peek` |
| `waiting` | `glance` |
| `happy` | `glance` |
| `sad` | `glance` |

### 6.4 状态流转规则

1. 当事件队列为空时：
   - `mood = none`
   - `state = dormant`
   - 关闭所有面板
   - 右胶囊不可聚焦
2. 当有非风险事件时：
   - 默认 `state = glance`
   - 鼠标进入刘海命中区或键盘 focus 进入胶囊时，切到 `peek`
   - 鼠标离开且未手动展开时，回到 `glance`
3. 当有风险事件时：
   - 默认 `state = peek`
   - 风险胶囊必须主动完整探出
4. 点击右胶囊：
   - 如果有事件，进入 `expanded + action`
   - 如果无事件，展示 toast：`当前没有需要处理的事件`
5. 点击左胶囊：
   - 进入 `expanded + sessions`
6. 点击面板外或按 `Esc`：
   - 收起面板
   - 回到当前 mood 的静息 state
7. 事件被 resolve 后：
   - 当前事件标记为 `resolved`
   - 队列自动选择下一个最高优先级事件
   - 如果无剩余事件，回到 `dormant`

## 7. 优先级和队列规则

### 7.1 默认优先级

| 事件类型 | priority | 展示策略 |
| --- | --- | --- |
| `risk` | 100 | 主动探出 |
| `confirm` | 80 | 一瞥，悬停探出 |
| `error` | 70 | 一瞥，悬停探出 |
| `result` | 55 | 一瞥，低打扰 |

### 7.2 排序规则

1. 只展示 `status = active` 的事件。
2. 按 `priority` 从高到低排序。
3. 同优先级按 `createdAt` 从新到旧排序。
4. 同一会话同类型事件可合并，但风险事件不得被普通事件覆盖。
5. 当前胶囊只展示排序后的第一条事件。
6. 事件数量显示所有 active 事件数量。

### 7.3 去重规则

| 场景 | 去重方式 |
| --- | --- |
| 同一会话重复完成提醒 | 保留最新一条，旧事件标记 `expired` |
| 同一命令重复确认 | 按 `sessionId + commandHash` 合并 |
| 同一错误持续出现 | 合并为一条错误事件，更新次数和最近时间 |
| 多个风险命令 | 不合并，逐条处理 |

## 8. 功能设计

### 8.1 顶部状态层

#### 功能说明

顶部状态层是产品的主入口，包含固定刘海、左会话胶囊、右事件胶囊和休眠眼。

#### 输入

- 当前事件队列。
- 当前会话列表。
- 当前窗口/显示器尺寸。
- 用户显示偏好。

#### 输出

- `data-state`
- `data-mood`
- `data-panel`
- 左右胶囊可见性。
- 可访问名称和焦点状态。

#### 规则

1. 刘海本体尺寸固定，不因事件变化被撑大。
2. 胶囊从刘海两侧滑出，而不是替代刘海。
3. 无事件时只显示休眠眼。
4. 右胶囊优先级高于左胶囊。
5. 左胶囊是辅助入口，默认不得抢右侧事件注意力。
6. 小屏或无刘海环境下，顶部状态层使用菜单栏浮动模式。

#### 验收标准

- 无事件时屏幕顶部视觉占用接近 0。
- 风险事件出现后，右胶囊自动进入完整可见状态。
- 鼠标悬停刘海区域时，非风险事件从一瞥进入探出。
- 键盘 focus 胶囊时，也能进入探出。
- 小屏下左右胶囊不得溢出视口。

### 8.2 右侧事件胶囊

#### 功能说明

右胶囊展示当前最需要处理的事件，是用户进入操作面板的主入口。

#### 展示内容

| 区域 | 内容 | 说明 |
| --- | --- | --- |
| 左 | DMG 形象表情 | 随 mood 变化 |
| 中 | 状态词 | `风险`、`确认`、`完成`、`失败` |
| 右 | 事件数量 | active 事件数 |

#### 文案规则

| 事件类型 | 胶囊状态词 | 可访问名称 |
| --- | --- | --- |
| `risk` | 风险 | `{session.name} 风险，{count} 项待处理` |
| `confirm` | 确认 | `{session.name} 确认，{count} 项待处理` |
| `result` | 完成 | `{session.name} 完成，{count} 项待处理` |
| `error` | 失败 | `{session.name} 失败，{count} 项待处理` |
| 无事件 | 全部安静 | `没有待处理事件` |

#### 交互

- 点击：打开操作面板。
- Hover：从 `glance` 进入 `peek`。
- Focus：从 `glance` 进入 `peek`。
- 无事件时点击：toast 提示，不打开面板。

#### 验收标准

- 右胶囊默认只呈现一条当前事件，不显示会话名和时间。
- 表情不得被数字、文字或边框遮盖。
- 完成态表情应温和，不可呈现阴森或警示感。
- `eventCount` 为 0 时不应以警示样式强调。
- 胶囊宽度应可在桌面和移动宽度下稳定展示。

### 8.3 左侧会话胶囊

#### 功能说明

左胶囊提供全部 AI 会话入口，展示聚合信息，不用于抢占当前事件优先级。

#### 展示内容

- 工具标识堆叠：Claude、Codex、Qwen 或用户启用的工具。
- 会话总数。
- 活跃会话数。
- 待处理事件总数。

#### 可见规则

1. `dormant`：隐藏。
2. `glance`：默认隐藏或极弱显示，避免干扰右侧事件。
3. `peek`：可见。
4. `expanded`：可见。

#### 交互

- 点击打开会话面板。
- 当前无事件时仍可通过设置允许常驻会话入口，但默认关闭。

#### 验收标准

- 左胶囊不应比右胶囊更醒目。
- 当右侧是风险事件时，左胶囊应弱化。
- 点击左胶囊后焦点进入会话面板。

### 8.4 会话面板

#### 功能说明

会话面板用于扫读和切换全部 AI 会话。

#### 内容结构

1. 面板标题：`全部会话`
2. 活跃会话数量 badge
3. 会话列表
4. 底部操作：`静音普通运行`、`偏好`

#### 会话行字段

| 字段 | 说明 |
| --- | --- |
| 工具头像 | 工具标识 |
| 会话名 | `Claude CLI` 等 |
| 来源和项目 | `iTerm · notch-ai-monitor` |
| 待处理数量 | 当前会话 active 事件数 |
| 状态文案 | `运行中`、`空闲`、`待处理` |

#### 交互规则

1. 点击有待处理事件的会话：
   - 选择该会话第一条 active 事件。
   - 打开操作面板。
2. 点击无待处理事件的会话：
   - 保持会话面板。
   - toast 提示：`{session.name} 当前没有待处理事件`。
3. 点击 `静音普通运行`：
   - 普通 running 事件不进入右胶囊。
4. 点击 `偏好`：
   - 打开偏好设置。

#### 验收标准

- 会话列表按待处理数量和最近活动排序。
- 每个会话待处理数量与事件队列一致。
- 点击会话后，右侧操作面板内容正确切换。

### 8.5 操作面板

#### 功能说明

操作面板用于处理当前事件，是产品最核心的工作流区域。

#### 内容结构

1. 事件类型 eyebrow：`Risk`、`Confirm`、`Done`、`Error`
2. 事件标题
3. 会话名和时间
4. severity chip
5. 会话 tabs
6. 事件摘要
7. 风险原因列表
8. 命令预览或结果入口
9. 详情折叠区
10. 事件分页
11. 主动作按钮

#### 空状态

当没有 active 事件时：

- 标题：`当前没有事件`
- 文案：`AI 会话正常运行`
- body：`所有 AI 会话都在安静运行。`
- 分页：`0 / 0`
- 动作按钮为空。

#### 交互规则

- 点击会话 tab：切换到该会话第一条 active 事件。
- 点击上一条/下一条：在 active 队列中循环切换。
- 键盘 `ArrowLeft`/`ArrowRight`：展开操作面板时切换事件。
- 点击动作按钮：按动作定义执行。
- 事件 resolve 后：自动切换到下一条 active 事件。

#### 验收标准

- 面板必须完整展示当前事件的决策信息。
- 不同事件类型展示不同动作。
- 所有会话 tab 的事件数量准确。
- 分页和键盘切换同步更新胶囊、标题、详情和动作。
- 事件处理后不应停留在已处理事件上。

### 8.6 风险事件工作流

#### 触发条件

- AI 请求执行危险命令。
- 命令涉及不可恢复删除、权限提升、批量覆盖、敏感目录、网络外发等。
- 系统检测到风险等级为 high 或 critical。

#### 展示策略

- mood：`angry`
- state：默认 `peek`
- 胶囊状态词：`风险`
- severity chip：`risk`
- 必须展示风险证据。

#### 必须展示的信息

| 信息 | 说明 |
| --- | --- |
| 命令全文 | 不可截断关键危险参数 |
| 风险原因 | 例如删除范围过宽、包含 `git clean` |
| 影响范围 | 文件路径、仓库、进程、权限 |
| 来源 | AI 生成、尚未执行、用户触发 |
| 撤销方案 | 可撤销、不可撤销、备份建议 |

#### 默认动作

| 动作 | 样式 | resolves | 说明 |
| --- | --- | --- | --- |
| 拒绝执行 | danger | 是 | 阻止命令执行 |
| 允许一次 | primary | 是 | 仅本次放行，需要二次确认 |
| 定位终端 | secondary | 否 | 跳转到来源终端 |
| 复制命令 | secondary | 否 | 复制到剪贴板候选区 |

#### 验收标准

- 风险事件不得被完成或错误事件覆盖。
- `允许一次` 必须有二次确认。
- 未展示命令和影响范围时，不允许执行 `允许一次`。
- 拒绝后事件关闭，并记录 resolution。

### 8.7 确认事件工作流

#### 触发条件

- AI 请求运行命令。
- AI 请求读取、写入或生成文件。
- AI 需要用户确认下一步策略。

#### 展示策略

- mood：`waiting`
- state：默认 `glance`
- 胶囊状态词：`确认`

#### 默认动作

| 动作 | 样式 | resolves | 说明 |
| --- | --- | --- | --- |
| 批准运行 | primary | 是 | 允许继续执行 |
| 拒绝 | secondary/danger | 是 | 阻止执行 |
| 定位终端 | secondary | 否 | 跳到来源 |
| 复制命令 | secondary | 否 | 复制命令 |

#### 验收标准

- 命令预览必须可完整查看。
- `批准运行` 后事件 resolve，并向对应会话发送 approval。
- `拒绝` 后事件 resolve，并向对应会话发送 rejection。

### 8.8 完成事件工作流

#### 触发条件

- AI 长任务完成。
- 生成了文件、报告、草稿、代码修改或可查看结果。

#### 展示策略

- mood：`happy`
- state：默认 `glance`
- 胶囊状态词：`完成`
- 表情温和，不使用强警示光效。

#### 默认动作

| 动作 | 样式 | resolves | 说明 |
| --- | --- | --- | --- |
| 打开结果 | primary | 是 | 打开文件、URL 或结果目录 |
| 标记已读 | secondary | 是 | 不打开结果，关闭提醒 |
| 复制摘要 | secondary | 否 | 复制结果摘要 |
| 定位会话 | secondary | 否 | 跳到来源会话 |

#### 验收标准

- 完成态不得主动抢焦点。
- 完成事件可设置自动收回时间。
- 打开结果失败时应转为 error 或 toast 提示。

### 8.9 错误事件工作流

#### 触发条件

- AI 会话失败。
- 命令执行报错。
- 本地端口占用、权限不足、依赖缺失。
- 会话超时或失联。

#### 展示策略

- mood：`sad`
- state：默认 `glance`
- 胶囊状态词：`失败`

#### 默认动作

| 动作 | 样式 | resolves | 说明 |
| --- | --- | --- | --- |
| 重试 | primary | 是 | 重试当前任务或命令 |
| 查看日志 | secondary | 否 | 打开日志面板 |
| 终止旧服务 | secondary/danger | 是 | 针对端口占用等场景 |
| 忽略 | secondary | 是 | 关闭提醒 |

#### 验收标准

- 错误必须展示原因和日志片段。
- 重试失败应生成新的 error 事件或更新当前事件。
- 终止进程类动作必须二次确认。

### 8.10 Toast 和 live region

#### 功能说明

toast 用于展示轻量操作反馈，live region 用于辅助技术读取状态变化。

#### 规则

- toast 默认显示 2100ms。
- 同一时间只显示一个 toast。
- toast 内容同步写入 `aria-live="polite"`。
- 高风险确认不使用 toast 替代正式对话。

#### 验收标准

- 执行动作后用户能看到结果反馈。
- 屏幕阅读器可以读到关键反馈。

### 8.11 偏好设置

#### MVP 偏好项

| 监控 Codex CLI | 开 | 是否监控 Codex |
| 监控 Qwen CLI | 开 | 是否监控 Qwen |

#### 验收标准

## 10. 可访问性和键盘

### 10.1 必须支持

- HTML 语言为 `zh-CN`。
- 所有按钮有可访问名称。
- 状态变化写入 live region。
- `Esc` 收起面板。
- `ArrowLeft`/`ArrowRight` 切换事件。
- `Tab` 可进入左右胶囊和面板动作。
- `Enter`/`Space` 可触发按钮。
- 支持 `prefers-reduced-motion`。

### 10.2 焦点规则

1. 打开会话面板后，焦点进入会话面板容器。
2. 打开操作面板后，焦点进入操作面板容器。
3. 关闭面板后，焦点返回触发胶囊。
4. 事件被处理后，如果仍有下一条事件，焦点留在操作面板。
5. 无事件后，焦点返回右胶囊或主容器。

### 10.3 验收标准

- 不使用鼠标也能处理所有 MVP 事件。
- 屏幕阅读器能听到当前事件类型、来源、数量和动作结果。
- 减少动效模式下不出现大幅滑动和持续呼吸动画。

## 11. 响应式和显示器适配

### 11.1 MacBook 刘海模式

- 使用屏幕顶部中心作为锚点。
- 刘海尺寸固定。
- 胶囊从刘海左右侧滑出。

### 11.2 无刘海/外接显示器模式

- 使用顶部菜单栏居中或靠右浮动胶囊。
- 不显示物理刘海图形。
- 仍保留左右胶囊和面板关系。

### 11.3 小窗口/窄宽度

- 宽度小于 760px 时，胶囊改为屏幕左右安全边距定位。
- 面板宽度使用 `min(372px, 100vw - 24px)`。
- 面板居中展示，避免溢出。

### 11.4 验收标准

- 390px 宽视口下胶囊和面板不溢出。
- 外接显示器无刘海时不出现假的硬件刘海。
- 多显示器切换时位置自动更新。

## 12. 隐私和安全

### 12.1 数据处理原则

- 默认只在本地处理会话和事件数据。
- 命令、路径、日志属于敏感数据，不上传云端。
- 风险扫描尽量本地完成。
- 用户允许命令执行前必须看到命令和影响范围。

### 12.2 敏感动作二次确认

以下动作必须二次确认：

- 允许风险命令执行。
- 终止进程。
- 删除文件。
- 修改权限。
- 写入敏感目录。
- 将命令或日志发送到外部服务。

### 12.3 验收标准

- 风险命令不能绕过用户确认。
- 日志和命令不会在未授权情况下上传。
- 二次确认弹窗明确展示目标动作和影响范围。

## 15. 验收用例

### 用例 1：无事件休眠

前置：事件队列为空。  
操作：打开应用。  
期望：

- `state = dormant`
- `mood = none`
- 只显示刘海休眠眼
- 右胶囊不可点击

### 用例 2：确认事件

前置：Qwen 产生 confirm 事件。  
操作：用户 hover 刘海并点击右胶囊。  
期望：

- 默认 `glance`
- hover 后 `peek`
- 点击后打开操作面板
- 显示命令、原因、影响、批准/拒绝按钮

### 用例 3：风险事件

前置：AI 请求执行危险命令。  
操作：事件进入队列。  
期望：

- 自动 `peek`
- 胶囊显示 `风险`
- 面板展示命令全文和风险原因
- `允许一次` 需要二次确认
- `拒绝执行` 后切换到下一事件

### 用例 4：完成事件

前置：Claude 完成任务并产出文件。  
操作：点击右胶囊，点击打开结果。  
期望：

- 胶囊显示 `完成`
- 表情温和，非警示
- 打开结果后事件 resolve
- 队列为空时回到休眠

### 用例 5：错误事件

前置：Codex 预览服务端口被占用。  
操作：打开操作面板，点击查看日志或重试。  
期望：

- 显示错误原因和影响
- 查看日志不 resolve
- 重试成功后 resolve，失败后更新错误事件

### 用例 6：多事件分页

前置：队列有 risk、confirm、error、result。  
操作：打开操作面板，点击下一条。  
期望：

- 默认展示 risk
- 分页为 `1 / 4`
- 下一条按排序切换
- 胶囊数量保持 4

### 用例 7：会话面板

前置：有 3 个会话，其中 Qwen 有 2 个待处理。  
操作：点击左胶囊，再点击 Qwen 行。  
期望：

- 会话面板显示 3 个会话
- Qwen 行显示 2 待处理
- 点击后打开 Qwen 对应操作事件

### 用例 8：键盘流

前置：有 confirm 事件。  
操作：Tab 到右胶囊，Enter 打开，ArrowRight 切换，Esc 关闭。  
期望：

- focus 后进入 `peek`
- Enter 打开操作面板
- ArrowRight 切换事件
- Esc 关闭面板并回到静息状态
